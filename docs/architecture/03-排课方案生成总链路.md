# 03-排课方案生成总链路

> 更新时间：2026-05-18  
> 当前方向：正式生成链路已收敛为“遗传算法全局搜索 + LightGBM 局部评分”。

---

## 概述

排课方案生成链路是 edu-flow-ai 的核心流程。教务创建排课任务、绑定教学任务后，系统自动生成多套候选方案，经由约束校验、教师画像解释、方案评估后提交教务确认。

最终目标不是让 LLM 直接生成课表，也不是让 LightGBM 直接决定整套方案，而是采用：

```text
Java 业务编排层
  负责任务管理、教师画像 RAG 解析、生成流程调度、约束校验、结果入库

Python 智能计算层
  负责候选片段生成、LightGBM 局部评分、遗传算法全局优化
```

---

## 总链路

```text
① 创建排课任务
  教务在前端创建 allocation_task，绑定 teaching_task
        ↓
② 策略因子生成
  预设策略 / LLM 翻译自然语言 / 手动调整全局权重
        ↓
③ 教师画像结构化
  Java 构造参与教师集合 Query
  → Embedding
  → Qdrant 按 teacherId 精确过滤
  → LLM 结构化为 teacher_penalties.json
  → MySQL 文本解析 fallback
        ↓
④ 候选池构建
  Python 构造每个教学任务片段的候选：时间片 × 教室
  → 周末硬过滤
  → 基础硬约束标记
  → 规则预筛 candidate_pool_size
        ↓
⑤ LightGBM 局部评分
  对单个候选片段计算 predicted_score
  学习来源：历史反馈、人工调整、规则样本
        ↓
⑥ 遗传算法全局优化
  一个个体 = 一整套排课方案
  一个基因 = 一个片段选择的候选时间 + 教室
  fitness 综合：模型分、硬冲突、教师画像、分布均衡、策略权重
        ↓
⑦ 方案评估
  evaluate_scheme_demo.py 计算方案级指标、画像满意度、冲突统计
        ↓
⑧ Java 入库
  allocation_scheme / allocation_item / conflict_check_result
        ↓
⑨ 前端展示与人工微调
  候选方案评分、课程表视图、冲突说明、画像扣分说明、拖拽调整
        ↓
⑩ 反馈学习
  人工选择、拖拽、确认进入反馈数据 → 重训 LightGBM → 下一轮生成优化
```

## 算法边界

| 模块 | 职责 | 不负责 |
|---|---|---|
| LLM | 策略语言翻译、教师画像文本结构化 | 不直接生成课表、不直接决定候选 |
| LightGBM | 单个候选片段质量评分 | 不搜索完整课表、不处理全局最优 |
| 遗传算法 | 完整方案层面的全局搜索 | 不学习历史偏好，只调用评分与约束 |
| 规则/约束 | 硬冲突检测、周末硬过滤、容量/类型约束 | 不替代模型评分 |
| Java | 编排、数据准备、画像解析、结果入库、状态推送 | 不做智能搜索 |
| 前端 | 策略选择、方案解释、人工调整、反馈入口 | 不直接修改算法内部参数 |

## LightGBM + GA 评分模型

### 1. 候选片段评分

LightGBM 负责给单个候选片段打分：

```text
candidate = teaching_task_fragment × time_slot × classroom
predicted_score = LightGBM(candidate_features)
```

该分数只代表“这个片段本身是否像历史上的好安排”，不代表整套课表最优。

### 2. 遗传算法个体

```text
Individual = [gene_1, gene_2, ..., gene_n]
Gene = 某个教学任务片段选中的一个候选
```

每个基因从对应片段的 top-N 候选池中选择，避免 GA 在过大的原始空间里乱撞。

### 3. 适应度函数

第一版建议：

```text
fitness =
  avg_predicted_score * predicted_score_weight
  + avg_rule_score * rule_score_weight
  - hard_conflict_count * hard_conflict_penalty
  - teacher_profile_penalty_total * teacher_profile_penalty_scale
  - distribution_penalty_total * distribution_penalty_scale
  + classroom_stickiness_bonus * classroom_stickiness_weight
  + compact_bonus * compact_bonus_weight
```

硬约束采用巨大惩罚，周末不排课直接在候选生成阶段过滤，不进入 GA 搜索空间。

## GA 默认参数建议

| 参数 | 默认值 | 说明 |
|---|---:|---|
| population_size | 80 | 每代完整方案数量 |
| generations | 80 | 迭代代数 |
| elite_size | 8 | 每代保留的最优个体数 |
| tournament_size | 4 | 锦标赛选择规模 |
| mutation_rate | 0.08 | 基因变异概率 |
| candidate_pool_size | 500 | 模型打分前的规则预筛池 |
| candidate_top_n | 30 | 每个片段进入 GA 的候选数 |
| predicted_score_weight | 100 | LightGBM 分数权重 |
| rule_score_weight | 10 | 规则分权重 |
| hard_conflict_penalty | 1000 | 教师/班级/教室时间冲突惩罚 |
| capacity_penalty | 500 | 容量不足惩罚 |
| room_type_penalty | 500 | 教室类型不匹配惩罚 |
| teacher_profile_penalty_scale | 100 | 教师画像软约束惩罚放大系数 |
| distribution_penalty_scale | 20 | 分布不均惩罚放大系数 |
| classroom_stickiness_weight | 10 | 同任务教室稳定奖励 |
| compact_bonus_weight | 10 | 紧凑排课奖励 |
| exclude_weekends | true | 周末时间片硬过滤 |

前端第一阶段不暴露这些底层参数，只提供“快速预览 / 标准优化 / 高质量优化”三档即可。

## 关键设计决策

1. **LLM 不直接参与排课决策**：只负责语义翻译和教师画像结构化。
2. **LightGBM 不直接生成整套方案**：只作为局部片段评分器。
3. **遗传算法负责全局搜索**：在完整课表层面综合约束与目标函数。
4. **硬约束优先于权重**：周末、容量、教室类型、时间冲突不能靠调权重解决。
5. **教师画像作为可解释软约束**：命中时保留扣分说明，前端展示为“画像扣分”。
6. **人工调整进入反馈闭环**：形成“算法生成 → 人工微调 → 反馈重训 → 再生成优化”。
