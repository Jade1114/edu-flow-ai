## ⚠ 待实现

### P0：③ LLM + Qdrant 教师画像结构化惩罚

**当前**：`generate_scheme_demo.py` 通过 MySQL 直读 `teacher_profile` 表，正则解析文本。

**目标**：LLM 构造 Query → Embedding → Qdrant 检索 → LLM 阅读画像全文 → 输出结构化惩罚参数。

**涉及文件**：
- `server/ml/scripts/generate_scheme_demo.py`：新增 `resolve_teacher_penalties()` 函数
- 复用已有能力：`OpenAiEmbeddingClient`（Embedding）、`QdrantVectorStoreClient`（向量检索）、`OpenAiChatClient`（LLM 调用）

**实现要点**：

1. 根据教学任务列表构造检索 Query
   - 输入：`teaching_tasks`（含课程名、教师名、班级名）
   - 拼接为自然语言："Java程序设计-张明-软件1班；数据库原理-李娜-软件1班..."

2. 调 Embedding API 获取 Query 向量

3. 调 Qdrant 检索 topN 相关教师画像
   - 取回画像全文（available_time_text / unavailable_time_text / workload_requirement / special_note）

4. 调 LLM 将画像转为结构化惩罚参数
   - System prompt：定义输出格式
   - User prompt：画像全文 + 教学任务上下文
   - 输出 JSON：
     ```json
     {
       "teacher_penalties": {
         "teacher_id": {
           "unavailable_slots": [[day, period], ...],
           "max_weekly_hours": 8,
           "penalty_weight": 0.05,
           "reason": "周三课题组会议"
         }
       }
     }
     ```

5. 替换现有 `fetch_teacher_profiles()` 调用

**依赖**：需要 Qdrant 服务运行，且教师画像已入库向量索引。

### P0：⑤ 评估器纳入教师画像满意度

**当前**：`evaluate_scheme_demo.py` 只算硬件指标（片段数、冲突数、分布均衡度等）。

**目标**：评估器接收 `teacher_penalties`，输出画像满意度分。

**涉及文件**：
- `server/ml/scripts/evaluate_scheme_demo.py`

**实现要点**：

1. 新增 `--teacher-penalties` CLI 参数
2. 对每套方案计算：
   - `teacher_satisfaction` = 所有排课片段对教师画像的符合率
   - 被不可用时间命中的片段数 / 总片段数 → 越低越好
   - 超出画像偏好课时的教师数 → 越少越好
3. 纳入 `scheme_score` 计算公式
4. 输出到 `scheme_xxx.json` 中
