## P0：GA 切换前结构清理

**目标**：在实现 `generate_scheme_ga.py` 前，明确哪些旧链路要迁移、删除或保留，避免第三次重构后项目继续臃肿。

### 必须清理

| 残留 | 位置 | 原因 | 处理方式 |
|---|---|---|---|
| 逐片段生成正式入口 | `server/ml/scripts/generate_scheme_demo.py` | greedy/top-k-random 只适合 baseline，不再作为最终主链路 | 迁移可复用函数后删除或改名为历史实验脚本 |
| Java 固定调用旧脚本 | `AllocationMlSchemeService.java` | 当前仍调用 `scripts/generate_scheme_demo.py` 且传 `--strategy top-k-random` | 切到 `scripts/generate_scheme_ga.py`，移除 `--strategy/--top-k` |
| Python 内置教师画像 RAG | `generate_scheme_demo.py` 中 `resolve_teacher_penalties()` / `build_teacher_penalty_query()` / `PROMPT_DIR` | 教师画像解析已经回到 Java，Python 不应再持有 LLM/RAG 编排职责 | GA 脚本只读取 Java 写入的 `teacher_penalties.json` |
| Python 侧教师画像 Prompt | `server/ml/prompts/teacher-penalty-*.md` | 当前 Java 使用 `server/src/main/resources/prompts/teacher-penalty-*.md`，ML prompt 已变成重复来源 | 删除 ML 目录下重复 prompt |
| 文档中的旧入口表述 | `docs/`、`server/ml/README.md` | 容易误导后续维护者继续使用旧链路 | 统一改为 GA 主链路 + LightGBM 局部评分 |

### 应该保留

| 能力 | 位置 | 原因 |
|---|---|---|
| LightGBM 训练 | `train_lightgbm.py` | GA 仍需要局部候选评分 |
| 反馈样本构建 | `build_feedback_training_samples.py` | 反馈闭环核心 |
| 方案评估 | `evaluate_scheme_demo.py` | GA 输出仍需要方案级评估 |
| Java 教师画像解析 | `TeacherPenaltyResolver.java` | 画像 RAG/LLM 编排归 Java |
| Qdrant/Embedding 客户端 | `rag/*` | 教师画像检索仍依赖 |
| 策略翻译 | `PolicyTranslateController.java` | 只处理全局策略权重，不处理个体教师偏好 |
| 画像扣分解释展示 | `AllocationView.vue` | 保证方案可解释 |

## P0：GA 参数设计确认

第一版默认参数建议：

```json
{
  "population_size": 80,
  "generations": 80,
  "elite_size": 8,
  "tournament_size": 4,
  "mutation_rate": 0.08,
  "candidate_pool_size": 500,
  "candidate_top_n": 30,
  "predicted_score_weight": 100,
  "rule_score_weight": 10,
  "hard_conflict_penalty": 1000,
  "capacity_penalty": 500,
  "room_type_penalty": 500,
  "teacher_profile_penalty_scale": 100,
  "distribution_penalty_scale": 20,
  "classroom_stickiness_weight": 10,
  "compact_bonus_weight": 10,
  "exclude_weekends": true
}
```

前端第一阶段只暴露三档模式：

| 模式 | population_size | generations | 使用场景 |
|---|---:|---:|---|
| 快速预览 | 40 | 40 | 调试、快速看结果 |
| 标准优化 | 80 | 80 | 默认生成 |
| 高质量优化 | 120 | 150 | 演示/最终排课 |

## P1：端到端链路验收

**验收路径**：

```text
创建/选择排课任务
↓
选择预设策略或输入自然语言策略
↓
GA 生成候选方案
↓
查看方案评分、冲突、教师画像扣分说明
↓
调整一个排课片段
↓
确认候选方案
↓
检查 course_assignment 正式课表是否更新
↓
检查旧正式课表是否置为 INACTIVE
↓
检查反馈/调整日志是否可导出训练样本
```

**重点检查**：

- `AllocationMlSchemeService` 是否调用 `generate_scheme_ga.py`。
- GA 输出 CSV 是否保持 Java 解析契约。
- `evaluate_scheme_demo.py` 是否仍能评估 GA 输出。
- 前端是否正确区分红色硬冲突和黄色画像扣分。
- 生成中刷新页面/切路由后，前端是否能通过 `generation-status` 恢复进度并重连 SSE。
- 删除分课任务后，候选方案、正式课表、反馈、调整日志、冲突记录是否被级联清理。
