# 排课系统架构设计

## 系统链路

```
教务创建排课任务 + 选择生成策略
               ↓
    ┌──── 参数翻译（可选） ────┐
    │  POST /api/param/translate │
    │  LLM 翻译自然语言 → 策略权重 │
    └─────────┬─────────────────┘
               ↓
  ╔═══════════╧════════════════════════════╗
  ║    自训练模型方案生成 (Java → Python)   ║
  ║                                         ║
  ║  Java 调 Python generate_scheme_demo.py ║
  ║  传入：teaching_task_ids + policy + weeks║
  ║  输出：N 个 scheme_*.csv + 评估 JSON    ║
  ╚═══════════╤════════════════════════════╝
               ↓
    ┌─────────┴──────────┐
    │  Java 解析 CSV 入库  │
    │  → allocation_scheme │
    │  → allocation_item   │
    └─────────┬───────────┘
               ↓
    ┌─────────┴──────────┐
    │  冲突检测            │
    │  → conflict_check_result │
    └─────────┬───────────┘
               ↓
    ┌─────────┴──────────┐
    │  页面展示多方案       │
    │  → 综合评分 + 维度分  │
    │  → 策略标签           │
    └─────────┬───────────┘
               ↓
        教务选择 / 调整 / 确认
               ↓
    ┌─────────┴──────────┐
    │  反馈记录落库         │
    │  → allocation_scheme_feedback │
    │  → allocation_item_adjustment_log │
    └─────────┬───────────┘
               ↓
        正式课表发布
    → course_assignment
```

## 核心组件

### 1. 自训练模型 (LightGBM)

| 属性 | 说明 |
|------|------|
| 模型文件 | `server/ml/models/schedule_ranker_v1.txt` |
| 职责 | 对候选安排（任务×时间片×教室）评分 |
| 训练数据 | 规则构造样本 + （后续）反馈回流样本 |
| 更新方式 | 增量训练 → 新 model.txt → 灰度上线 |

### 2. 方案生成器

| 组件 | 位置 |
|------|------|
| Python 生成 | `server/ml/scripts/generate_scheme_demo.py` |
| Java 调用 | `AllocationMlSchemeService.java` |
| 方案解析入库 | `AllocationSchemeGenerationService.java` |

生成参数：

```
--variant-count    方案数量（默认 3）
--strategy         选择策略（greedy / top-k-random）
--top-k            top-k 候选池大小
--candidate-pool-size    规则预筛池大小
--policy           生成策略 profile
--teaching-task-ids      教学任务 ID 集合
--start-week / --end-week  周次范围
```

### 3. 方案评估器

| 组件 | 位置 |
|------|------|
| Python 评估 | `server/ml/scripts/evaluate_scheme_demo.py` |
| 调用时机 | Java 生成 CSV 后自动调用 |
| 输出 | `scheme_XXX.json`（维度评分 + 原始指标）|

评估指标：

| 指标 | 含义 | 范围 |
|------|------|------|
| scheme_score | 综合分（硬冲突 + 负载均衡 + 早晚课）| 0~100 |
| teacher_score | 教师体验分（负载均衡 + 早晚课惩罚）| 0~100 |
| class_balance_score | 班级均衡分 | 0~100 |
| room_util_score | 教室利用分 | 0~100 |
| compact_score | 紧凑度（天数集中程度）| 0~100 |
| hard_conflict_count | 硬冲突数 | ≥0 |
| weekday_distribution | 星期分布 | JSON |
| period_distribution | 节次分布 | JSON |

### 4. 生成策略（Policy Profile）

5 种预设策略，通过权重影响候选选择函数：

| 策略 | 特点 | 适用场景 |
|------|------|----------|
| BALANCED | 各项权重均衡 | 默认综合方案 |
| TEACHER_FRIENDLY | 降低教师负载、避免早晚课 | 教师满意优先 |
| CLASS_BALANCED | 班级课表均衡 | 学生体验优先 |
| ROOM_EFFICIENT | 教室使用集中 | 资源利用率优先 |
| COMPACT | 压缩到更少天数 | 紧凑型课表 |

策略定义位置：`server/ml/scripts/generate_scheme_demo.py` 中 `POLICY_PROFILES`。

Java 端默认值：`AllocationMlSchemeService.DEFAULT_POLICY = "BALANCED"`。

选择函数：

```python
selection_score = model_predicted_score
                + rule_score * 0.02
                - weekday_load * policy.weekday_load_penalty
                - room_day_load * policy.room_day_load_penalty
                - task_day_load * policy.task_day_load_penalty
                - early_period * policy.early_period_penalty
                - late_period * policy.late_period_penalty
                + compact_bonus * policy.compact_bonus_weight
                + random_jitter * policy.random_jitter
```

### 5. LLM 参数翻译接口

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/param/translate` | POST | 自然语言 → 策略参数 |

请求体：

```json
{
  "policyType": "BALANCED",
  "extraRequirement": "张老师不要早八，李老师希望周三少课",
  "teacherProfiles": { "101": { "avoidEarly": true } }
}
```

响应体：

```json
{
  "policyParams": {
    "weekday_load_penalty": 0.006,
    "room_day_load_penalty": 0.004,
    "teacher_101_early_penalty": 0.05
  },
  "interpretation": "已优先考虑教师个人偏好"
}
```

## 数据库设计

| 字段 | 类型 | 说明 |

| 字段 | 类型 | 说明 |

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | |
| scheme_id | BIGINT FK | |
| item_id | BIGINT | 被调整的 item |

## 反馈闭环

```
方案生成
    ↓
页面展示（评分 + 维度 + 策略标签）
    ↓
教务选择方案 → feedback_type=SELECTED
    ↓
教务拖拽调整 → allocation_item_adjustment_log
    ↓
教务确认方案  → feedback_type=CONFIRMED
    ↓
反馈数据积累到阈值
    ↓
构造新训练样本 + 旧数据
    ↓
重新训练 LightGBM → v2 model.txt
    ↓
v1 vs v2 对比评估
    ↓
灰度上线 / 全量切
```
