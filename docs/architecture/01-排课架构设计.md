# 排课系统架构设计

## 系统链路

```
教务创建排课任务 + 选择生成策略
               ↓
    ┌──── 参数翻译（可选） ────┐
    │  POST /api/param/translate │
    │  LLM 翻译自然语言 → 策略权重 │
    └─────────┬─────────────────┘
               ↓
  ╔═══════════╧════════════════════════════╗
  ║    GA + LightGBM 方案生成 (Java → Python) ║
  ║                                           ║
  ║  Java 调 Python generate_scheme_ga.py     ║
  ║  传入：teaching_task_ids + policy + weeks  ║
  ║  输出：N 个 scheme_*.csv + 评估 JSON      ║
  ╚═══════════╤════════════════════════════╝
               ↓
    ┌─────────┴──────────┐
    │  Java 解析 CSV 入库  │
    │  → allocation_scheme │
    │  → allocation_item   │
    └─────────┬───────────┘
               ↓
    ┌─────────┴──────────┐
    │  冲突检测            │
    │  → conflict_check_result │
    └─────────┬───────────┘
               ↓
    ┌─────────┴──────────┐
    │  页面展示多方案       │
    │  → 综合评分 + 维度分  │
    │  → 策略标签           │
    └─────────┬───────────┘
               ↓
        教务选择 / 调整 / 确认
               ↓
    ┌─────────┴──────────┐
    │  反馈记录落库         │
    │  → allocation_scheme_feedback │
    │  → allocation_item_adjustment_log │
    └─────────┬───────────┘
               ↓
        正式课表发布
    → course_assignment
```

## 核心组件

### 1. 自训练模型 (LightGBM)

| 属性 | 说明 |
|------|------|
| 模型文件 | 优先使用最新成功反馈重训版本，fallback 到 `schedule_ranker_v1.txt` |
| 职责 | 对候选安排（任务×时间片×教室）做局部片段评分 |
| 训练数据 | 规则构造样本 + 反馈 JSON 转换样本 |
| 更新方式 | 版本化重训 → 训练日志记录 → 生成链路选择最新成功模型 |

### 2. 方案生成器（目标）

| 组件 | 位置 |
|------|------|
| Python 生成 | `server/ml/scripts/generate_scheme_ga.py` |
| Java 调用 | `AllocationMlSchemeService.java` |
| 方案解析入库 | `AllocationSchemeGenerationService.java` |

生成入口：

```text
Java / ML API
  → run_ga_pipeline_by_task(allocation_task_id)
    → 读取 allocation_task_generation_config
    → 读取 allocation_task_teaching_task 绑定
    → 读取教师画像并生成 teacher_penalties.json
    → 运行 GA + LightGBM
```

`generate_scheme_ga.py` 不再支持 CLI 参数启动；方案数量、允许时间范围、软权重都来自任务配置表。GA 种群规模、迭代代数、候选池大小等算法工程参数暂时保留为 Python 常量。

`generate_scheme_ga.py` 是当前正式生成入口。

### 3. 方案评估器

| 组件 | 位置 |
|------|------|
| Python 评估 | `server/ml/scripts/evaluate_scheme_demo.py` |
| 调用时机 | Java 生成 CSV 后自动调用 |
| 输出 | `scheme_XXX.json`（维度评分 + 原始指标）|

评估指标：

| 指标 | 含义 | 范围 |
|------|------|------|
| scheme_score | 综合分（硬冲突 + 负载均衡 + 早晚课）| 0~100 |
| teacher_score | 教师体验分（负载均衡 + 早晚课惩罚）| 0~100 |
| class_balance_score | 班级均衡分 | 0~100 |
| room_util_score | 教室利用分 | 0~100 |
| compact_score | 紧凑度（天数集中程度）| 0~100 |
| hard_conflict_count | 硬冲突数 | ≥0 |
| weekday_distribution | 星期分布 | JSON |
| period_distribution | 节次分布 | JSON |

### 4. 生成策略（Policy Profile）

前端可以提供策略预设作为配置模板，但 Python 生成器不再识别 `BALANCED` / `COMPACT` 等策略字符串。

正式生成时，Java / ML API 按 `allocation_task_id` 触发 `run_ga_pipeline_by_task(task_id)`，Python 从 `allocation_task_generation_config` 读取数值权重并映射为候选选择函数使用的 `rule_weights`。

选择函数：

```python
selection_score = model_predicted_score
                + rule_score * 0.02
                - weekday_load * policy.weekday_load_penalty
                - room_day_load * policy.room_day_load_penalty
                - task_day_load * policy.task_day_load_penalty
                - early_period * policy.early_period_penalty
                - late_period * policy.late_period_penalty
                + compact_bonus * policy.compact_bonus_weight
                + random_jitter * policy.random_jitter
```

### 5. LLM 参数翻译接口

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/param/translate` | POST | 自然语言 → 策略参数 |

请求体：

```json
{
  "policyType": "BALANCED",
  "extraRequirement": "张老师不要早八，李老师希望周三少课",
  "teacherProfiles": { "101": { "avoidEarly": true } }
}
```

响应体：

```json
{
  "policyParams": {
    "weekday_load_penalty": 0.006,
    "room_day_load_penalty": 0.004,
    "teacher_101_early_penalty": 0.05
  },
  "interpretation": "已优先考虑教师个人偏好"
}
```

## 数据库设计

### allocation_scheme（扩展后）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | |
| task_id | BIGINT FK | 所属排课任务 |
| scheme_name | VARCHAR | 方案名称 |
| summary | TEXT | 摘要 |
| scheme_score | DOUBLE | 评估器综合分 0~100 |
| evaluation_summary | TEXT | 评估结果 JSON（含维度评分）|
| policy | VARCHAR(32) | 生成策略名称 |
| policy_params | TEXT | 策略参数 JSON |
| model_version | VARCHAR(16) | 模型版本号 |
| conflict_summary | TEXT | 冲突摘要 |
| valid | BOOLEAN | 是否有效 |

### allocation_scheme_feedback

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | |
| scheme_id | BIGINT FK | 对应方案 |
| task_id | BIGINT FK | 对应任务 |
| feedback_type | VARCHAR(30) | SELECTED / ADJUSTED / CONFIRMED |
| adjustment_count | INT | 调整次数 |

### allocation_item_adjustment_log

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | |
| scheme_id | BIGINT FK | |
| item_id | BIGINT | 被调整的 item |
| from_time_slot_id / to_time_slot_id | BIGINT | 调整前后时间段 |
| from_classroom_id / to_classroom_id | BIGINT | 调整前后教室 |
| reason | VARCHAR(500) | 调整原因 |

## 反馈闭环

```
方案生成
    ↓
页面展示（评分 + 维度 + 策略标签）
    ↓
教务选择方案 → feedback_type=SELECTED
    ↓
教务拖拽调整 → allocation_item_adjustment_log
    ↓
教务确认方案  → feedback_type=CONFIRMED
    ↓
反馈数据积累到阈值
    ↓
构造新训练样本 + 旧数据
    ↓
重新训练 LightGBM → v2 model.txt
    ↓
v1 vs v2 对比评估
    ↓
灰度上线 / 全量切
```
