# 02-模型反馈训练闭环

## 概述

edu-flow-ai 的排课模型（LightGBM）支持**反馈驱动的持续优化**。前端操作（生成方案、拖拽调整、确认/拒绝方案）产生的反馈数据，可被导出为训练样本，用于重训模型，形成"生成→检测→反馈→重训"闭环。

## 当前能力

- ✅ 前端操作（生成方案 / 拖拽调整 / 编辑教室与时间片 / 确认方案）已落库为反馈数据
- ✅ 后端 `GET /api/ml/feedback/export` 手动导出反馈为 JSON
- ✅ Python 脚本将反馈 JSON 转为 LightGBM 训练样本 CSV
- ✅ 后端 `POST /api/ml/feedback/train` 基于最近一次 JSON 触发重训
- ✅ 后端 `GET /api/ml/feedback/training-status` 查询训练状态
- ✅ 模型训练入口集中在模型训练中心，分课任务页不再保留训练按钮

## 反馈数据源

| 数据表 | 反馈类型 | 标签策略 |
|--------|----------|----------|
| `allocation_scheme` | 方案级评分/状态 | 确认方案 → 正样本，拒绝方案 → 负样本 |
| `allocation_item` | 排课明细 | 确认明细 → 正样本 |
| `allocation_scheme_feedback` | 教务确认/拒绝 | CONFIRMED→正，REJECTED→负 |
| `allocation_item_adjustment_log` | 人工拖拽/编辑调整 | 调整前→负，调整后→正 |
| `conflict_check_result` | 规则冲突 | 有冲突明细→负样本 |

## 样本标签策略

| 样本来源 | score（标签） | weight | 说明 |
|----------|:------------:|:------:|------|
| 已确认方案明细 | 1.0 | 1.0 | 强正反馈 |
| 被拒绝方案明细 | 0.0 | 0.5 | 弱负反馈 |
| 冲突明细 | 0.0 | 1.3 | 强负反馈 |
| 调整前（旧时间/教室） | 0.0 | 1.2 | 软负反馈 |
| 调整后（新时间/教室） | 1.0 | 1.4 | 强正反馈 |

权重设计原则：人工直接操作 > 规则判定 > 系统自动标记。

## 行为转反馈规则

| 用户行为 | 当前记录方式 | 训练语义 |
|---|---|---|
| 拖拽排课片段 | 后端 `moveAndRecheck()` 自动写 `allocation_item_adjustment_log`，reason=`修改时间片` | 调整前负样本，调整后正样本 |
| 编辑排课片段教室 | 后端自动写调整日志，reason=`修改教室` | 原教室负样本，新教室正样本 |
| 同时编辑时间片+教室 | 后端自动写调整日志，reason=`修改时间片+教室` | 原组合负样本，新组合正样本 |
| 确认方案 | 写入 `allocation_scheme_feedback(CONFIRMED)`，并统计 `adjustment_count` | 方案明细正样本 |
| 冲突检测 | `ALLOCATION_ITEM` 冲突或 `allocation_item.valid=false` | 强负样本 |

## API 接口

### GET /api/ml/feedback/export?taskId={taskId}
导出指定排课任务（或全部）的反馈数据为 JSON。

**响应：**
```json
{
  "code": 200,
  "data": {
    "exportPath": "ml/data/feedback/exports/feedback_task_1_20260516100123.json",
    "schemeCount": 3,
    "itemCount": 45,
    "feedbackCount": 1,
    "adjustmentCount": 5,
    "conflictCount": 2,
    "sampleCount": 0
  }
}
```

### POST /api/ml/feedback/train?taskId={taskId}
基于最近一次手动导出的反馈 JSON 生成训练 CSV，并重训 LightGBM。

**前置条件：** 先调用 `GET /api/ml/feedback/export?taskId={taskId}` 生成反馈 JSON。

**响应：** 异步返回训练状态（同步阻塞，完成后返回最终状态）。

### GET /api/ml/feedback/training-status
查询最近一次训练状态。

**状态值：** `IDLE` / `RUNNING` / `SUCCEEDED` / `FAILED`

## Python 脚本

### build_feedback_training_samples.py

将后端导出的反馈 JSON 转为 LightGBM 训练 CSV。

```bash
python3 ml/scripts/build_feedback_training_samples.py \
  --input ml/data/feedback/exports/feedback_task_1_20260516.json \
  --output ml/data/feedback/samples/feedback_samples_task_1_20260516.csv
```

**输出特征（约 54 列）：**
- 基础特征：sample_id, teaching_task_id, candidate_classroom_id, candidate_time_slot_id
- 课程特征：course_type, total_hours, required_room_type, class_group_count, total_student_count
- 教师特征：teacher_department, teacher_title, teacher_max_weekly_hours
- 教室特征：room_capacity, room_type, room_building, capacity_margin, capacity_ratio
- 时间特征：week_number, day_of_week, period_index, is_morning, is_afternoon, is_evening, is_weekend, is_early_period, is_late_period
- 教师画像特征：teacher_matrix_value, teacher_preferred_max_weekly_hours, teacher_avoid_first_period, teacher_avoid_last_period, teacher_prefer_compact_schedule, teacher_preferred_weekday_match, teacher_avoid_slot_match
- 占用特征：teacher_occupied_at_slot, class_occupied_at_slot, room_occupied_at_slot
- 负载特征：teacher_day_load, class_day_load, teacher_week_load, class_week_load, scheme_day_load, room_day_load, room_week_load, task_day_load
- 约束特征：is_capacity_enough, is_room_type_match
- 冲突标记：has_teacher_conflict, has_class_conflict, has_room_conflict, has_hard_conflict
- 标签：sample_weight, score, reject_reason

### 重训流程

```text
GET /api/ml/feedback/export
  ↓
1. 从 DB 导出反馈 JSON
  ↓
POST /api/ml/feedback/train
  ↓
Java: MlFeedbackTrainingService.train()
  ↓
2. 读取最近一次反馈 JSON
  ↓
3. 调用 build_feedback_training_samples.py 生成 CSV
  ↓
4. 调用 train_lightgbm.py 重训模型
  ↓
5. 新模型写入 `ml/models/feedback/current/schedule_ranker.txt`，历史版本归档到 `ml/models/feedback/archive/<timestamp>/`
  ↓
返回训练结果 / 状态
```

## 限制与下一步

### 当前限制
- **非增量训练**：每次重训使用完整数据集（反馈样本 + 原始训练样本），不支持在线增量更新。
- **同步阻塞**：训练接口为同步调用，大样本量时可能超时，建议后续改为异步任务。
- **模型版本管理**：当前仅输出固定文件名，无版本回滚机制。
- **阈值/策略**：标签权重为经验设定，需根据实际使用迭代调整。
