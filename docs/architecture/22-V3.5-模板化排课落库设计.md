# V3.5 — 模板化排课落库设计

> 状态：设计草案  
> 更新时间：2026-06-08  
> 目标：支撑 V3.5 周模板排课、按周套模板、整体换周和后续局部调整。

## 一句话定义

V3.5 不直接只保存最终展开课表，而是保存：

```text
模板
  ↓
每周使用哪个模板
  ↓
模板内有哪些片段
  ↓
片段实际占用哪些课段
```

这样后续要交换两周课程时，只需要交换 `week -> template` 映射，不需要重写模板片段。

## 核心表

### 1. `schedule_template`

记录一次排课任务生成出来的模板实体。

用途：

- 保存模板编码，如 `cover_v1_template_1`。
- 记录模板属于哪个 `allocation_task_id`。
- 记录算法版本、模板顺序、片段数、任务数。

对应算法输出：

```text
template_cover_v1.json.templates[]
```

### 2. `schedule_template_week`

记录某个排课任务中，每一周使用哪个模板。

用途：

- 查询第 N 周应该套用哪份模板。
- 支持两周整体互换。
- 支持后续人工把某周切到另一个模板。

换周操作只改这张表：

```sql
UPDATE schedule_template_week
SET template_id = :newTemplateId
WHERE allocation_task_id = :allocationTaskId
  AND week_number = :weekNumber;
```

### 3. `schedule_template_fragment`

记录模板中的一个教学片段。

一个 fragment 表示：

```text
某个教学任务
在某个模板里
占用某个教室
从某天某课段开始
连续占用 consecutive_slots 个课段
```

对应算法输出：

```text
template.fragments[]
```

### 4. `schedule_template_fragment_slot`

记录 fragment 实际占用的每一个课段。

例如上机课：

```text
fragment: 周二第 3 段开始，consecutive_slots = 2
实际占用：
  周二第 3 段
  周二第 4 段
```

用途：

- 快速做模板内冲突检测。
- 查询某模板某时间段有哪些课。
- 避免每次查询时动态展开 `consecutive_slots`。

### 5. `schedule_timetable_entry`（可选）

最终周课表展开表。

MVP 阶段可以不急着使用，因为通过：

```text
schedule_template_week
+ schedule_template_fragment
+ schedule_template_fragment_slot
```

已经能动态查询任意周课表。

如果后续前端或 Java 查询压力较大，再把模板展开成 `schedule_timetable_entry` 缓存。

## Dry-run 数据文件

当前 Python 侧先不直接写 DB，而是将 `template_cover_v1.json` 导出成准备入库的 JSONL：

```text
backend/models/v3.5/placement/db_draft/schedule_templates.jsonl
backend/models/v3.5/placement/db_draft/schedule_template_weeks.jsonl
backend/models/v3.5/placement/db_draft/schedule_template_fragments.jsonl
backend/models/v3.5/placement/db_draft/schedule_template_fragment_slots.jsonl
```

这些文件字段尽量与 SQL 表一致，方便人工 review 后再接真实 insert。

## 周模板映射策略

V1 采用简单策略：

```text
第 1 周 -> cover_v1_template_1
第 2 周 -> cover_v1_template_2
第 3 周 -> cover_v1_template_1
第 4 周 -> cover_v1_template_2
...
```

即模板按周轮换。

原因：当前 `template_cover_v1` 的多模板含义是“剩余任务增量模板”，不是严格周段模板。先用轮换策略验证数据库结构和换周能力。

后续可以升级为：

```text
根据 fragment.week_mask 统计每个模板最适合覆盖哪些周
再生成 schedule_template_week
```

## 换周验证

如果第 5 周和第 8 周互换：

- 不修改 `schedule_template`。
- 不修改 `schedule_template_fragment`。
- 不修改 `schedule_template_fragment_slot`。
- 只交换 `schedule_template_week` 中两行的 `template_id/template_code`。

这就是模板化落库的核心收益。

## 当前边界

- `teaching_task_id/classroom_id/teacher_id/class_group_id` 当前 dry-run 可能为空，先使用 `source_key/name` 做过渡。
- 当前模板来自 V3.5 Python 实验产物，尚未接 Java 生产入库。
- 教师字段在训练样本里大量为空，教师冲突和 teacher_id 映射后续需要 DB 侧补齐。
- `schedule_timetable_entry` 暂时是可选缓存表，不是 MVP 必需表。
